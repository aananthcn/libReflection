# 0008 — Registry & Thread-Safety Model

**Status:** Decided

## Context

`FindByHash`/`FindByName` (0003) need a global registry mapping every
registered type to its `ClassReflection`. Registration happens via
static/global objects created by the `REFLECT_*` macros, which raises
the classic static-initialization-order problem, and the registry
itself may be read from multiple threads.

## Decision

- **Per-type reflection storage:** a function-local `static const
  ClassReflection` inside the `Reflect<T>()` specialization generated by
  the macros (Meyer's singleton). C++11 "magic statics" guarantee
  thread-safe, exactly-once initialization for function-local statics —
  supported by GCC, Clang, and QCC's underlying compiler on both Linux
  and QNX SDP 8.0 — so no manual locking is needed for the
  per-type-first-access path, and there is no static-init-order fiasco
  because nothing runs until first called.
- **Global name/hash registry:** a single `std::unordered_map` (keyed
  by `ClassHash` and, separately, by name), itself a function-local
  static (same magic-statics safety), guarded by a `std::mutex` on every
  insert *and* every lookup. The `Reflect<T>()` specialization inserts
  itself into this registry the first time it runs.
- Locking every lookup (rather than optimizing for a read-mostly
  workload with something lock-free) is a deliberate simplicity choice:
  registration is a one-time, low-frequency operation in practice
  (typically all at process startup), so contention is not a realistic
  concern, and a plain mutex is far easier to get correct on a new
  target (QNX) than a lock-free structure.

## Consequences

- No explicit "init the reflection system" call is ever required —
  everything is lazy, triggered by first use.
- `FindByHash`/`FindByName` only find types that have actually been
  `Reflect<T>()`'d (directly, or as a nested member of something that
  has) at least once by the time of the call — a type that exists in
  code but whose `Reflect<T>()` was never instantiated/called is
  invisible to runtime lookup. This is inherent to lazy registration
  and should be noted in README.md so it isn't mistaken for a bug.
